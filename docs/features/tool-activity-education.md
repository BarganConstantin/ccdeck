## Five comprehension findings

1. Concrete operation names lack general-purpose explanations.
2. Median/P95 definitions in the inspector assume statistical vocabulary.
3. Native titles do not supply visible keyboard/touch education.
4. Raw inspector rates on small samples are qualified only in collapsed details.
5. Pointer inspection appears abruptly, while high-volume keyboard navigation
   should remain immediate.

## Implemented teaching system

`operation-glossary.ts` contains fourteen exact, typed purpose/basis entries.
No argument parsing, suffix matching, remote lookup or AI interpretation occurs.
Unknown names retain identity and a neutral, explicitly unverified fallback in
the inspector. Unconfirmed `multi_agent_v1_wait_agent` is not aliased to the
verified double-underscore identity. Purpose is never proof of a recorded effect.

Charts and table reuse the chrome hint through `ToolAuditOperationButton`.
Mouse rest and keyboard focus reveal verified purposes; P95 hints retain exact
recorded milliseconds and measured counts. Accessible names carry equivalent
content; touch selects the operation and reads its persistent inspector purpose.
No secondary explanation repeats under every ranking row. Unknown tools are not
given guessed purposes. Charts/table expose expanded state and the common
inspector target for selected identities.

`tool-audit-education.ts` supplies plain definitions for unique calls,
containing-call memberships, cumulative intervals, Median, P95, sample minimum,
timing coverage, reported outcomes/rates, shared intervals, dates and clocks.
The detailed reading guide is explicitly requested within Coverage & definitions;
it does not displace snapshot/observed-data facts. A small P95 help trigger and
its counterpart in inspector Measured intervals reuse `AnchoredPopover`.
The heading gets initial focus, Escape/Done returns to the anchor, and the
popover stays within the viewport with bounded scrolling when necessary.
Its dismissal layer matches its report overlay position; other consumers keep
existing defaults. The existing hint optionally follows a focused scrolling
operation and flips/clamps to available space; chrome consumers keep defaults.

Inspector purpose is persistent, with the no-arguments/output limitation.
Small-sample raw failure rates now have an immediate descriptive-sample note.
P95 uses the existing eligibility helper, including unavailable values below20.
No collector, aggregation or provider timing semantics are modified.

## Motion and bounded refinement

Report entrance and refresh feedback are preserved. Pointer-only inspector
entry fades from0.6opacity over160ms using the house curve. Keyboard opening is
immediate; reduced motion disables entry. Closing is immediate to avoid delaying
focus return. Chart elements and filter reorders are not animated. The help
popover uses the existing120ms entrance only for pointer input; keyboard entry
is immediate. No new motion dependency or continuous decorative effect.

Rendered critique moved the large guide behind its own disclosure and focused
help headings before long content so short popovers start at their beginning.
Functional diagnosis separated test actionability scrolling from actual clicks:
a tooltip under a stationary automated pointer could make Playwright scroll a
row before click. The scroll-preservation regression now moves the pointer away
and clicks the visible row's screen coordinates; no unnecessary shared focus
change is retained. Keyboard focus scrolling genuinely hid row hints; the
opt-in focused-anchor behavior retains visible keyboard education.
