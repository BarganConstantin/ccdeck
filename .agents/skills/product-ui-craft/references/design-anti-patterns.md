# Failure patterns and practical defenses

| Failure pattern | Check before acting |
|---|---|
| Over-simplification | Does removing detail hide a decision, trust cue or necessary action? Restore useful hierarchy rather than stripping personality. |
| Cosmetic loops | Which user problem does the next color/border/spacing edit solve? No new evidence means stop. |
| Large empty layout | Does extra width/height improve actual task area and content grouping? Measure useful space, not modal size. |
| Excessive vertical expansion | Inspect stretching, headings, separators and repeated metadata. Establish aligned compact rows with adequate targets; do not blindly shrink padding. |
| Ambiguous interaction | Does selection actually filter or navigate, and is its result apparent? Informational counts must not mimic controls. |
| Missing state coverage | Check real transitions, errors, expanded/long content and short windows before approval. |
| Misleading semantic color | Distinguish depleted capacity, stale data, errors, current selection and active monitoring. Include a non-color cue. |
| Generic decoration | Remove purposeless nested cards, random gradients/glows, metric widgets, badges and icons on every line. Keep purposeful character and actual product identity. |
| Premature sign-off | A screenshot cannot prove keyboard, runtime data or integration correctness. State evidence and gaps. |
